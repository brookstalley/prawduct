# Learnings — tests

Rules that fire while writing or changing a test. **Reading a rule is not applying it.** Name the rule and say what it changes about the decision in front of you, or say that it does not apply.

- Hand-verifying at the terminal leaves nothing behind: the real corpus you grepped IS a fixture, so make it one in the same breath. Tell: "I checked it against the real file" with no test naming it
- A mutant SURVIVING on code you just wrote is a claim about the CODE: ask which existing branch already answers the case. Tell: no fixture makes guarded and unguarded differ — unreachable; delete the guard, pin the GUARANTEE
- A mutation test is evidence only if the MUTANT IS THE DEFECT: restore the code that shipped the bug, gate conditions included, and mutate each CONJUNCT separately — `A and B` reverted whole leaves B unpinned
- When you cite a precedent ("shape mirrors X"), COPY `test_X.py` FIRST and port its cases — its tests enumerate the branches its design creates; borrowing the design alone ships them untested and the gap looks like correct code
- When a predicate classifies REAL artifacts, at least one test must read the real artifact — a hand-written fixture only confirms your belief. Tell: you grepped the real corpus to WRITE fixtures; that proved it walkable, so walk it
- RESTORE THE WAY YOU MUTATED: invert the exact replacement, never `git checkout -- <file>`, which reverts to HEAD and takes other uncommitted edits with it. Tell: the file carries unrelated WIP and the undo is file-wide
- A test asserts what would BREAK, not what you just built — red-verify mechanically: break the subject, watch that specific test go red, restore. Vacuous shapes look correct while proving nothing
- A NEGATIVE assertion forbids everything its wording matches — match the exact string carrying the excluded behaviour, and always pair it with a POSITIVE assertion for the behaviour that must survive
- When a test asserts a VALUE and its comment says the value feeds a downstream contract, assert the CONTRACT — the comment does reasoning the test never performs (agent name checked, `hooks.json` matcher never opened)
- When a test injects a fixed clock, EVERY actor must share that clock — one real-clock participant (a CLI front, an un-injected default) turns fixed stamp + TTL into a scheduled failure at stamp+TTL wall time
- When a requirement is about a COST, assert the operation that costs, not a proxy that usually accompanies it. Tell: the test names a side effect ('was the file read') where the requirement names work ('was the directory walked')
- Test subprocesses with HOME=tmp_path (== the test repo) leak macOS Python's pyc cache into it as untracked files, skewing git-status-based helpers — point HOME at a directory OUTSIDE the test repo
- When a deliberate change turns a passing test red, renegotiate the contract in the open — rename the test to the new contract, invert the assertion, document why, keep still-valid invariants explicit; never silently relax or delete it
- A deletion's SURVIVORS owe new coverage when their behaviour changed — the deleted thing's tests dying correctly is a different question from whether the code left behind is still pinned
- Never chain a test-evidence `record` after a suite run in one command, nor trust a piped suite's exit code (`| tail` exits 0 on red) — read the run's own summary, then record as a separate step; a false-green record pollutes the gate
- A repo-coupled test that reads committed docs/state makes every 'doc-only' change a silent test-breaker — doc-only and test-status fast paths assume non-code can't change outcomes. Make it robust to expected state changes, or its inputs judgeable
- Relocating importable code behind a conftest sys.path shim: standalone `__main__` scripts don't get the shim (conftest fires only under pytest) — grep for scripts that self-insert the old root and fix each.
- A guard test pinning a safety claim asserts the PROPERTY, not one spelling — a literal match (flag token, grant string, substring) passes every rewording of the defect; verify it red against a DIFFERENT phrasing than the one that prompted it.
- When the deliverable is INSTRUCTIONS, at least one guardrail must model the READER — size, budget and right-words-present tests all pass while the instruction has no effect, because none reads the file in the order an agent reads it.
- A passing assertion may be satisfied by something else: an unimplemented flag passes because the arg guard REJECTED it (assert success before absence); a prose substring survives any longer sentence; a proxy passes — gate on the named event.
- A test inherits undeclared inputs (machine state, setup races) and unobserved properties — a stage whose worth is SPEED needs a test that fails when it slows. Mutation is one-directional (revert undoes damage and fix): pair it with branch coverage.
- 'Make A agree with B' has two solutions; the cheap one hands A B's defects and goes green with both wrong. Pin the DIRECTION separately, on a fixture from the population the predicate is worst at. Tell: every fixture sits inside the allowlist.
- A guardrail whose anchors come from your MENTAL MODEL of a file is a second copy of the claim, not a check — derive anchors by reading the file as you write the test, or it encodes the same error. Tell: you wrote anchors without opening the file.
- A green suite is evidence about the ONE environment that ran it — a suite only its maintainer runs has untested dependencies on that machine. Expect the first CI run to be red and treat that as the run working.
- Making a capability conditional on the RUNTIME conditions every test whose fixture touches it, not just ones you wrote — shared fixtures carry it. Simulate the degraded runtime over the whole file before commit; a reviewer will surface only one.
- When a check's subject is a SET, assert it is non-empty and holds what it names, or green means nothing was looked at. A report's internal consistency says nothing of its corpus — output corpus SIZE. Tell: 'every/all' about a set code assembled.
- A gate on a value nearly every fixture supplies touches nearly every fixture — estimate that blast radius in the plan; it changes the chunk's real size. Fix fixture DATA, never assertions. Tell: a title rule broke 100+ tests across eight modules.
- A test written RELATIVE to the constant it polices (`CONST - 1`) can't detect that constant being wrong — pin the absolute value when it's a historical fact (a stamped version, a shipped format). Tell: an expected-red mutation stayed green.
- A rule enforced only as a SIDE EFFECT of another failure is unenforced wherever the failure mode differs — ask what actually caught its incident. Tell: a mutation you expected caught survives, on a rule with a documented past incident.
- A structural guard firing on your own justified change is answered, never re-floored — record why the population moved in the assertion's docstring and pin what must NOT move. Tell: relaxing a floor because your change shrank its count.
- Fix and pin a defect at the LAYER IT WAS REPORTED AT — a test on the extracted predicate proves the predicate, not the wiring; deleting the CLI branch leaves it green. Tell: the finding says 'at the CLI' and your new test imports the module.
- An exemption filter on a self-referential test (dropping 'could not read X' candidates) goes GREEN wherever the subject is unreachable — CI, if X is gitignored. Assert the subject was REACHED. Tell: the filtered cause is a gitignored input.
- A test asserting its OWN repo's live state pins the current PHASE — a release empties it and the suite reds at the worst moment. Make it name WHICH emptiness it rejects ('just shipped' vs 'join broken'). Tell: reads the real tree, asserts nonempty.
- A test deriving its fixture from the mechanism under test turns that mechanism's failure into a SKIP, so the bug ships green — pick fixtures from an INDEPENDENT source (walk the dir, not the resolver) and `assert` the precondition, never skip.
- Prove a guard can go red — mutate a copy of the real corpus and watch each assertion fail; a consistent lie agrees with itself. Write surviving limits into the docstring under 'what turns this red'. Tell: you ran only the passing case.
- When a re-measurement CORRECTS a prior test, run it against the QUESTION, not the prior conclusion, or each instrument re-grades the last one's output. Ask what the check is a fact ABOUT. Tell: the re-measurement reuses the previous framing.
- An advisory's printed recommendation ships to every consumer repo — test its EFFECT: apply it on a fixture, observe the promised outcome, keep the un-applied case as control. Tell: every test asserts on the advisory object, none on following it
- An UNEXPECTED PASS is a signal, not a result — when a change you expected to break tests doesn't, find which branch they run before banking it; the fixture likely never reached the subject. Tell: predicted red, got green, explained it unopened
- A mutation sweep where EVERY mutant dies first pass is a claim about the HARNESS — assert each test RAN (return code, not output substring) and include one mutant you expect to live. A bad pytest flag "killed" 18/18 from a runner that never started
- When one rule is deliberately carried by two surfaces, pin it in a test reading BOTH — a bar reworded in one carrier is two bars no single-file guard sees. Bound the assertion to the smallest region carrying it. Tell: neighbour mutation stays green
- A fixture's world is narrower than the requirement: the common instance narrows it (check stated BREADTH); framework state stands in for what reaches consumer repos; one moment for the transitions; collisions go unwritten if the fan-out key repeats
- "Why is this a problem NOW?" is answered by a TREND — if a fail-open mechanism didn't change, the surface it fails over grew (path anchors 51→201), which picks the fix: mechanise, not hand-maintain. Tell: fixing the instance, can't say what changed
- To pin a DESIGN CONSTRAINT, mutate to the implementation it FORBIDS — it usually agrees on every buildable input, so force the degradation path it mishandles (stub rev-count to "?") and assert the verdict holds. Tell: no input where they differ
- A comment that NAMES a new failure mode owes a test in the same commit — unasserted, it reads as handled. Widening what an input may BE changes every branch consuming it: re-read the function, not the line. Tell: a comment names a case, no test
- When a guard is about WHERE something may appear, assert the COUNT and scan from the end the PARSER reads — a test slicing `rindex(fence)` passed while the FIRST opener hijacked the parse. Tell: guard says "first", test slices from the last
- A CLASS finding closed where it was NOTICED isn't closed — fix every site the finding names AND make a test fail for each; fixing both but pinning one lets the other be deleted green. Tell: finding says "both writers"/"every row", you test one
- When a fix NARROWS a detector, the verification set must include the TRUE POSITIVES it exists to catch, not just the false alarms you narrowed away — both read as zero findings. Tell: every shape you tested is one you were told was legal
- When every test INJECTS a dependency, green says nothing about how production OBTAINS it — drive a new consumer once with nothing injected; assert the seam is built (file-upstream got transport=None). Tell: threaded a param, never asked who sets it
- Defence in depth costs a test PER LAYER — an outer pre-check short-circuits every call, so the inner copy is a mutation survivor that reads as covered; enter each layer at its own door. Tell: you skipped mutating a rule verified on another arm
- A test pinning the ARITHMETIC doesn't pin the CALL — enter at the call site with input the narrowed and un-narrowed forms answer DIFFERENTLY, or the narrowing call deletes green. Tell: "pinned by <TestClass>" of a call site that class never invokes
- A comment saying "X still matches because Y" needs a test with X and no Y — else the suite is green under both the true mechanism and your wrong one, and the next author edits against it. Tell: survival credited to an input feature no test varies
- On stale test evidence, run the suite THROUGH `test-evidence record`, or run the declared command WITH --junit-xml and ingest via --from-junit (or a contract report); --from-counts is refused. Tell: test-status said stale, you reached for pytest
- An assertion against a CONTAINER (whole stdout, row, file) passes on any part — `"unreadable" in stdout` matched tmp_path, named after the test. Bind to the smallest span; add a control that must DIFFER. Tell: all new-path tests share a fixture
- Red CI over a green suite: enumerate EVERY axis the machines differ on before fixing — two-variable bugs need both (Linux+UTC+py3.10 `Z`). Prove the repro can FAIL first (GIT_CONFIG_SYSTEM=/dev/null misses Xcode's gitconfig). Tell: repro green
