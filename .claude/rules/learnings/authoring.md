# Learnings — authoring

Rules that fire while writing durable prose: methodology, docs, specs, records.

- A claim copied from a record — a [DECISION] block, a plan's VCS state, a quotation, a reflection, an owner-written issue — inherits its derivation, not its author: re-derive it from code, git or the source before propagating it.
- Scoping a NEW framework feature: list unmerged branches before writing requirements — this repo parks proposals on branches, so a HEAD-only grep of plugin/, .prawduct/ and backlog reads "no prior art". Tell: your search touched only paths on HEAD
- Rewriting a MEASUREMENT into a BENEFIT widens the claim — re-attach the number to the sentence you wrote. Tell: you cannot point at the number behind the noun you chose
- Retiring a MECHANISM: sort its rules into died / rewritten / INVERTED before deleting any — the lesson often outlives the tool, and an unnoticed inverted rule stays harmful. Tell: a prohibition whose reason was the tool
- Naming a chunk/scope/tag writes a MACHINE-READ field: check the parser's accepted form first — an unparseable value yields null, which is NO ANSWER and can silently switch off the gate. Tell: you chose an id for readability
- Pay a prose size ceiling in place: cut a class another file owns (dates, tallies, worked examples, duplicated definitions) — never move prose between files or trim the least-defended clause; otherwise declare a raise with its reason.
- When a trim lands under a pinned budget, lower its ceiling in the same commit. session-digest.md also has a hard 10,000-character wall (test_plugin_methodology_digest.py) that token budgets do not see.
- A new project-wide concept here (a build-plan field, governance flag or convention) cascades to the product anchor, the Critic and PR protocols, methodology, templates and their budget tests — list those surfaces in the chunk and expect the trim.
- Justify at the ALTITUDE OF THE DECISION, not the mechanism: a mechanism claim owes verification but escapes it as commentary. Must the reader reason past the instruction? No: cut the mechanism; yes (norm, decision): verify it like code
- Recording a scope narrowing (chunk deferred, work cut) is a CASCADE: plan bodies INSTRUCT against the changed fact — open every section naming that chunk, or a later chunk marks unbuilt work shipped
- When a skill has the model read then write with `--if-<field>`, verify the READ actually SURFACES the field the write consumes — a flag existing is not its input being obtainable; dogfood the handoff or write a read-then-feed test
- When compacting or migrating a tool-parsed file, classify every span by its CONSUMER first — machine-read metadata (parsed comments, `sentinel=` tags, status markers) must stay where its reader looks; a prose-preserved guard can't see it
- Requirements for replacing a working system: sweep every consumer's actual usage before finalizing — reported pain is a hypothesis, and the loudest complaint is often not the deepest failure
- Never write a present-tense state claim ("Phase 1 is complete") into a durable doc — write the dated measurement plus the command that re-derives it. Fires hardest inside a correction of someone else's stale claim
- When prose picks the model a reviewer/subagent runs on, express it as an ordered fallback chain resolved at dispatch — never a pinned alias
- 'I'm just codifying their guidance' is no exemption from the research trigger — owner-given CONTENT needs none, but its DESIGN or PLACEMENT in a fast-moving domain (Claude Code, agent methodology) does. Volatility is a separate axis from confidence
- A 'canonical' platform mechanism can be disqualified by a plugin's always-on + composable constraints — verify before adopting: Output Styles' `force-for-plugin` clobbers the user's style, so stance stays in the additive SessionStart digest
- Fanning a batch out to parallel worktree-isolated agents: partition by DISJOINT file ownership (the integrator owns any shared file, e.g. token-budget tests) and force-remove leftover worktrees before the integration suite — they don't auto-clean
- A new framework-wide DEFAULT must land in `session-digest.md` — the only surface every onboarded repo re-reads; place-once templates (project-preferences) and the thin CLAUDE.md anchor never reach already-onboarded repos
- A skill blocked reading its own bundled file under `--plugin-dir` is a dev-flag sandbox artifact, not a self-containment bug — add `--add-dir <plugin-path>`; a marketplace install grants plugin-tree reads. Don't 'fix' the skill's paths
- Apply principles when RECEIVING guidance, not just when changing framework files — check incoming designs for technology specificity, structural assumptions and instance-specific solutions
- Build-plan fields use `**Title Case:**` (e.g. `**Depends on:**`), not snake_case — the parsers match the Title Case form, and a snake_case field is silently unread
- Build-plan chunk parsers accept `### Chunk N:` and `## Chunk N (ID) — Name`, but NUMBER your chunks — the unticked-committed-chunk advisory matches `Chunk <n>` with a numeric id, so `Chunk A` gets permanent silence
- Verify the packaging boundary before duplicating a shared bundled file into each skill — a marketplace install copies the whole plugin tree, so one copy at plugin root works; a prior duplication may be an unverified-constraint workaround
- A format's schema legend authored from `templates/` is scaffold-only — adding an optional field needs BOTH a per-item backfill AND a legend-refresh step in migrate/triage, or onboarded repos get backfilled items no legend documents
- Scope a subsystem rebuild from the SPEC roster, not the open-work list — a backlog framed as 'the remaining N' assumes the shipped part still exists, and if a migration deleted it in between, the rebuild silently omits it
- A persisted schema's requirements are its consumers' future queries — lock-in is reversal cost, not LOC, so a 'small format' still gets decision research: ask 'what questions must this data answer over time?' before choosing a shape
- A cross-cutting concern named once in discovery but carried by no artifact, builder guidance or Critic check is UNCOVERED — audit the coverage matrix across all four columns for named-but-dropped, not just absent
- Before 'fixing' what looks like a forgotten manual update, check whether the artifact is GENERATED from a canonical source — a hand edit to a derived view is churn the generator overwrites; fix it upstream
- A subagent put in a worktree by PATH stays in yours: Bash `cd` does not persist between calls and skills fork in the session's dir — use `isolation: "worktree"`. Forks do follow EnterWorktree (measured, Claude Code 2.1.296).
- Before recommending changes to guidance material, have a fresh agent USE it on a real task — analytic review predicts defects that don't survive practice, and the trial shows which findings are real
- State precedence among alternatives RELATIONALLY ('BLOCKED wins any overlap'), never by position ('the earlier wins') — lists get reordered and the ordinal inverts while every word reads true. Tell: a worked example is what keeps the rule honest.
- When a shape changes, re-read every rule that POINTED AT the old shape — 'takes the second line' silently degrades from an instruction to a location once that slot holds several meanings, and a presence test pinning the rule stays green throughout.
- A spike that discards its code leaves its numbers unfalsifiable — commit the derivation as a runnable script and cite the COMMAND, never the digits, because a count transcribed into prose goes stale silently as the corpus grows.
- Exactness is owed to a number something RELIES ON for a decision, not one something merely READS — ask what branch changes if it is off by two; if none, the precision is waste. Verify the CONSUMER before defending a precision cost already paid.
- A deferral justified by 'no consumer yet' is scoped to surfaces that consumer doesn't touch — when one appears, restate the SCOPE as a ruling (don't retire the deferral or amend the decision) and list supported surfaces in ONE place others track.
- When a trim is justified by the surrounding prose's OWN instruction, run the suite before trusting it — the dangerous cut is the one the file appears to endorse; a restatement placed where the reader SKIPS the original is placement, not a copy.
- Derive what an instrument can OBSERVE before deciding what it is worth — a recommendation formed first makes verification a correction. Tell: you can name the gate's benefit but not the field it reads.
- 'Has this repo already decided it?' is the cheapest check that could change a design — run it BEFORE deriving, against every doc your source names as `**Parent:**`, not only `## Direction`; decisions also live in `documentation/`.
- A spec that deltas a parent corpus reads COMPLETE and its omissions are deliberate — 'this covers everything' is evidence of a delta. Tell: a design doc answering every question you asked, on a subsystem old enough to have been reviewed.
- Run the mechanical seeder BEFORE drafting, not as an audit — `prawduct-hook jurisdiction` ranks candidate governing artifacts by vocabulary overlap; run first it's an input, after it's a rewrite. Tell: about to write up a design you're happy with.
- A retirement is one act PER SUBSTRATE the thing lives on — read your rationale back before executing it and bound the edit to the backends each clause is about. Tell: the rationale names a backend, release or provider, and the diff names none.
- A REMEDY named in a checklist must be tested against the predicate that produced the condition — non-terminating advice gets obeyed ('re-run X until 0' when X consults the same refusal). Tell: the step names a command, not the reason's own remedy.
- Editing a norm's STATEMENT in the same commit as the code it would bless is the amend-to-match-own-code tell — record the departure beneath the clause and leave the clause alone. Tell: the edit admits just what you wrote.
- A rule that LOWERS a severity silently outranks every rule raising one — state the floor with the ceiling in one sentence; exits that lift a cap are not severities it may touch. Tell: you capped a severity and wrote only how to escape it
- One home stops DIVERGENCE, not staleness — adding a caller to shared copy, re-read the shared sentence as THAT surface's reader; a clause true for every old caller can be false at the new one. Tell: used the one home, never read the composed output
- When you add a rule at the site that motivated it, ENUMERATE the siblings performing the same ACT before calling it done — a criterion can be false at a surface you never opened. Tell: your fix names one call site, your criterion names a class
- Re-invoking a skill, hook payload or digest you just edited verifies NOTHING in the same session — the harness serves its cached pre-edit copy. Verify against disk or in a fresh session. Tell: your check is "run X, see the change" and X ran earlier
- Cutting prose because ANOTHER surface says it holds only for readers of that surface — the digest reaches the main agent, not subagents, so a building.md dedup deletes it for the delegate. Tell: "the digest states this" of a file subagents read
- A general policy sentence doesn't prove a specific procedure in the same doc inherits your addition — read the procedure end to end; if it RE-STATES the step, replace, don't supplement. Tell: you answered "does B inherit A?" from a class sentence
- In parallel multi-agent work the main integration cost is PROSE another agent's code falsified, not merge conflicts — disjoint files don't protect claims about mechanisms others change. Tell: an agent's files exclude the one DESCRIBING its change
- A chunk boundary defers a DELETION, never a CORRECTION — if your chunk falsifies a sentence a later chunk owns, fix the falsehood now and leave only the removal; a plan says where prose lives, not when it stopped being true
- A ruling recorded only where the deciders read it is NOT recorded — put it in the artifact the ASKERS receive, or "rule + filed as bug twice + no settlement" reads as an open bug. Tell: ruling in the change-log, the shipped copy has only the rule
- Instructions that drive code are sourced from the CODE's surface — read the handler; give every state, refusal code, envelope field and failure mode a line; the design only constrains. Tell: your skill cites design sections, the handler unopened
- Don't swap a visible placeholder for something that merely READS as working — skill shell state doesn't survive between tool calls, so "$SCRATCH" set earlier is empty later. Pin the dangerous half with a positive control. Tell: a blank looks real
- Mechanise only a QUERYABLE claim — owner goals and tradeoffs are judgment; an enum, tag schema or gate there becomes form-filling, and goals go unstated while you pick its shape. Tell: fields for what the owner would say in a sentence
