# Prawduct Changelog

Consumer-facing release notes for the Prawduct governance plugin. The
version-delta banner (a SessionStart hook) shows the headline for each version a
repo crosses since it was last opened — so an auto-update is always visible,
never silent. This file ships **inside the plugin**: it never lands in a
consuming repo's tree, so it creates zero commit/merge noise downstream.

The full internal development log (with blast-radius and rationale) lives in the
Prawduct repo's `.prawduct/change-log.md`; this file is the public digest. The
release process keeps the two in sync (one headline per shipped release).

## v2.1.2
Three fixes from the 2026-06-10 whole-framework audit — two gate-soundness holes and the biggest context-economy cost. (1) **The PR gate's ledger fallback now requires same-session freshness.** The fallback (which rescues a cumulative review after a later chunk review overwrites the findings file) accepted the newest qualifying ledger event with no recency bound, so a days-old cumulative from prior work could vouch for a new bundle whenever only `.md` changed since. It now requires the event's `ts >= .session-start` and fails closed — re-run `/prawduct:critic cumulative` this session if the gate tells you the only candidate predates it. (2) **A mis-set `active_build_plan` pointer can no longer silently blind governance.** The natural repo-relative spelling (`.prawduct/artifacts/…`) now resolves correctly in both resolvers, a pointer to a genuinely missing file gets a loud session-briefing warning naming the consequence (Critic gate, mode inference, and chunk-ref checks see no active plan), and the field is finally documented in the project-state template. (3) **`learnings.md` lookups got ~60% cheaper.** The framework's own learnings file had grown to ~80KB of narrative; entries are compacted back to their When-X-do-Y-because-Z rules (narrative preserved verbatim in `learnings-detail.md` under the same heading), and the session briefing now nudges any repo whose learnings.md exceeds 40KB. Bonus fix found on the way: the briefing's "Learnings (N rules)" line counted only bullet-format rules and silently showed nothing on entry-format files — it now counts `## ` entries.

## v2.1.1
The change-log lifecycle stops dropping work silently. Three failures observed across recent releases are closed: (1) **the statusless→merged stamp is now mechanical** — new `prawduct-hook stamp-merged` runs in the `/prawduct:pr` merge flow (convergent and idempotent, refuses to run anywhere but the integration branch), so entries no longer reach release-prep statusless and get skipped by a literal reading of the release checklist (v2.0.14 shipped 8 of 10 entries that way); the release checklist itself now says flip **every unreleased entry, statusless OR merged**. (2) **A code-changing branch can no longer merge without a change-log entry** — `prawduct-hook check-change-log-entry` gates `/prawduct:pr create`: any non-`.md` diff must ADD an entry header (doc-only branches exempt; fails closed on un-evaluable git state). (3) **Multiple tag lines per entry are unioned, not half-parsed** — `parse_change_log` previously honored only the first `<!-- prawduct: ... -->` line and silently dropped the rest (a `chunks=` tag nearly shipped unflipped at v2.1.0); now chunks union across lines and `regen-views` warns so you merge them. Plus: scope→plan validation now also covers statusless entries, catching a bad `scope=` before release instead of at it.

## v2.1.0
A review-governance release: reviews get **cheaper, risk-proportional, and observable** — plus hot-path session fixes. (1) **The re-review treadmill is gone (CRT-4J8W).** Fixing anything after a cumulative review used to re-stale the PR gate and cost a FULL bundle re-review (~4-10 min); now the gate accepts a **cumulative + verify-resolutions chain** — fix, commit, run `/prawduct:critic verify-resolutions`, and a 1-2 minute delta review extends the cumulative's vouching to HEAD (fail-closed on any scope gap). (2) **One full review per plan, not two:** a `Type: cumulative-final` last chunk lets the PR-gating cumulative BE the final review, and the **PR reviewer now consumes-and-audits the Critic record** (≥2 adversarial spot-checks) instead of re-deriving code soundness over the same diff. (3) **Reviews scale to risk:** reviewers default to opus (~4x faster per a captured A/B/C experiment), and `classify-diff-risk` escalates the model when the diff touches declared risk surfaces (gates, hooks, skills). (4) **Review work is now measurable:** an append-only governance ledger records every Critic/PR review (mode, model, duration, findings yield) and `prawduct-hook review-stats` aggregates cost/yield — proportionality tuning is evidence-driven now. (5) **Gate soundness for products:** the coverage gate only blocks on files it can actually judge (`changes_unjudged`), `test-evidence record` honors a declared `test_command:`/`tests_dirs:` (uv venvs, monorepos — no more wrapper scripts), build plans are tracked artifacts (the gitignore default + session untracking that broke multi-clone repos is retired and self-heals via `doctor`), and gate error messages teach the correct sequencing instead of leaving you to trial-and-error. (6) **Session hot-path fixes:** the version banner reads the real version again (a path-depth bug had it silently reporting "dev"), turn-end no longer runs a `gh pr list` network call on no-change sessions, git-quoted paths with spaces no longer break doc-only classification, and the work-model probe stops false-firing on acknowledgments/questions (common-English frequency floor + firing threshold). (7) **Less duplicated always-on context in the framework repo itself:** a slim session digest (~40% of full) when the governed repo is prawduct; product repos keep the full digest verbatim.

## v2.0.17
Two governance fixes that close review-gate holes. (1) **Your backlog now actually gets nudged to migrate.** After adopting a new prawduct version with an unstructured (legacy-format) backlog, you were supposed to see a session-start advisory pointing you to `/prawduct:backlog migrate` — but the probe that raises it (`legacy-backlog-format`) was never registered in the plugin runtime. It was the single production probe back in v1.7.0, got deleted with the file-sync engine, and the v0.3 backlog rework rebuilt only the *other* three probes, silently leaving the primary one out. It's restored: a backlog with more than five items none carrying a `[PFX-XXXX]` id now surfaces the migrate nudge, which clears itself once `backlog_format_version: 2` is recorded (what `/prawduct:backlog migrate` writes on completion). (2) **The PR-boundary "trivial" fast-path is retired.** `/prawduct:pr` had a fast-path that, based on the *fileset alone* (a change touching only existing files), would skip **both** the cumulative-Critic gate and the independent PR reviewer — so a substantial multi-chunk feature that only modified existing files could sail through with no review. Fileset-eligibility is a *necessary* but not *sufficient* signal of triviality, so the fast-path is gone; code PRs always get the full review now. The sound **doc-only** fast-path (an all-`.md` diff) and the per-chunk `Type: trivial` enforcement are unchanged.

## v2.0.16
Two follow-up fixes to the v2.0.15 backlog rework and the Critic. (1) **`/backlog migrate` now refreshes the schema legend, not just your items.** Adopting a new backlog field (v2.0.15's `stage:`/`refs:`/`accepted-by:`) backfilled your *items* but left the `backlog.md` header legend — authored once at onboarding — documenting the *old* schema, so a reader hit `stage: ready` with no key explaining it. `migrate` (and the triage method) now reconcile the legend to the current field set: **additive and non-destructive** (it fills in missing field docs and never touches a local extension like a `kind:` facet), idempotent, and it runs even when there are no legacy items. The optional-fields list in the skill that had omitted `stage:`/`refs:` is fixed too. (2) **The Critic picks the right mode on a feature branch again (CRT-7B4M).** On a `views_enabled` branch the build-plan Status checkboxes are a derived view that only flips at release, so they read all-unchecked during development — and `infer-critic-mode` was reading the *current* chunk from them, so it ran Chunk 01's mode on every chunk and could never detect the last chunk. It now derives chunk progress from git (the `Chunk <n>` commit subjects on the branch) when the checkboxes are an unflipped derived view, and degrades to the old behavior whenever the git signal doesn't apply — never worse than before.

## v2.0.15
The backlog gets a major rework — it now pulls its weight in multi-agent and lifecycle-aware workflows instead of sitting beside the work cycle. Five changes you'll feel: (1) **`accepted-by`** — a soft claim so a second agent or teammate doesn't pick up an item you're already on (`/prawduct:backlog pick`/`list` skip claimed items; it doesn't expire and isn't a hard lock — git is eventually-consistent — but it makes double-picks visible). (2) **`stage:`** — items now carry a lifecycle stage (`idea → research → requirements → design → ready`), and `pick` *routes* an early-stage or unstaged item to discovery/planning rather than letting you write code against an undocumented requirement (the Principle 6 hole the work-model feature started closing). (3) **Archive discipline** — "done" means the item moves to `## Archive`, never a strikethrough left inline (which silently cost context tokens every session); `/backlog migrate` now sweeps up existing strikeouts, and the janitor's new **Backlog Health** step surfaces stale/duplicate/unstaged items and proposes an archive split past ~200 entries. (4) **Stale-completion detection** — the Critic (C-B1–C-B4) and the PR reviewer (R-1/R-2) now flag backlog items your work appears to have resolved but left open, and dangling references — without ever inferring status (you still make the call). (5) **`/backlog import`** brings an existing `TODO.md`/`BACKLOG.md` into structured form, and three advisory probes nudge when an external backlog exists, the old section schema lingers, or a large backlog hasn't been groomed in 90 days. Under the hood: a real `lib/backlog.py` parser substrate (the count in your session briefing now derives from it), a `refs:` field linking items to their requirement/design docs, and `/backlog dedup`. Adopting is opt-in and additive — existing backlogs keep working untouched; run `/prawduct:backlog migrate` and the triage steps to bring one up to the new standard.

## v2.0.14
The independent Critic can no longer clobber the session it reviews. The Critic runs as a forked agent *directed* not to run executables, but the coordinator subagents it dispatches inherit the session's normal tool access — and in one incident a review subagent ran `prawduct-hook clear`, which is destructive: it archived the builder's in-progress reflection, reset the git baseline, and made fresh test evidence read "stale." Prawduct now enforces the real invariant — *an independent reviewer must never mutate the session it reviews* — at the mutation site: while a review is active (bracketed by new `critic-begin`/`critic-end` markers), a bare `prawduct-hook clear` refuses with an actionable override. The guard self-heals three ways (a 30-minute TTL, the next session-start sweep, and an explicit override) and fails *open* if the lib can't load, so it can never permanently block a session. Under the hood, this release also lands a large internal refactor (STH-9V4K): the monolithic governance hook was split into focused `lib/` modules — no change to how repos are governed, but a more maintainable, testable runtime. Two smaller fixes round it out: `/prawduct:pr` now redirects a `develop`→`main` release promotion to the documented release process instead of running feature-PR gates, and the build-plan chunk-reference check no longer trips on glob patterns written as prose.

## v2.0.13
Prawduct now catches *undocumented requirements* before they turn into code. Until now the framework guarded against requirement **loss** — it wouldn't let you silently drop one — but not requirement **absence**: you could describe a brand-new concept or domain model in a prompt and flow it straight into code with no requirement ever written down. A new deterministic check runs as you submit each prompt: it builds a lightweight vocabulary index from your governing artifacts (headings, bold terms, and an optional `vocabulary:` frontmatter list) and, when a prompt introduces salient terms no artifact covers, injects a quiet pre-turn nudge to locate or write the parent requirement first. It's fail-soft and only active in onboarded repos (gated on `.prawduct/`), and Principle 6 now states the rule both ways — never silently *drop* a requirement, and never silently *invent* one.

## v2.0.12
Turn Prawduct off in a repo with one command. Since the plugin installs for your whole machine, its commands and hooks load in every repo you open. The new **`/prawduct:repo-disable`** writes a per-repo `enabledPlugins` override that disables Prawduct here — `/prawduct:*` commands, hooks, and banner — either `committed` (`.claude/settings.json`, for everyone who clones the repo) or `local` (`.claude/settings.local.json`, auto-gitignored, just you). It preserves all your other settings and refuses to touch a malformed settings file. It takes effect after `/reload-plugins` or a restart. There's intentionally no re-enable command — once disabled, the plugin's own commands no longer load — so you re-enable by editing the file's `enabledPlugins` back to `"prawduct@prawduct": true` (the skill spells out the exact steps), or via Claude Code's native `/plugin` menu.

## v2.0.11
Prawduct now stays quiet in repos it doesn't govern. Because the plugin installs at the **user** level, its session hooks fire in *every* repo you open — and two of them used to speak up even in repos that never onboarded: the always-on guidance digest was injected everywhere, and a repo with source code but no `.prawduct/` got a `CRITICAL: create project-preferences.md` notice at session start. Both now gate on the same `.prawduct/` marker the version banner and the session-end gate already used, so an un-onboarded repo sees nothing from Prawduct's governance hooks. The one-line version banner (`═══ Prawduct vX ═══`) is intentionally kept as the always-on update-visibility signal, and the `/prawduct:*` commands stay available everywhere (they do nothing until you invoke them). To disable Prawduct entirely in a specific repo — commands included — set `"enabledPlugins": {"prawduct@prawduct": false}` in that repo's `.claude/settings.json` (or `.claude/settings.local.json` for just yourself). Onboard a repo and the hooks light up automatically.

## v2.0.10
Prawduct now notices when you skipped discovery. A repo you onboard with `/prawduct:onboard` and then work on **docs-first** — writing requirements/architecture before a discovery session — used to accumulate rich product docs while `project-state.yaml` stayed empty, and the framework said nothing (its only nudge was gated on source code existing). Now the session briefing emits a **DISCOVERY NOT CAPTURED** nudge when the state is still template-default but the repo shows real product work (code, or markdown under `docs/`/`documentation/`), routing you to `/prawduct:discovery` — which gains a documented **reconciliation mode** that reads your existing docs/code and backfills `project-state.yaml` rather than re-interviewing you. Onboarding and `/prawduct:doctor` both point at it. A freshly-onboarded empty repo stays quiet. If your repo already captured discovery, you'll notice nothing.

## v2.0.9
Governance-tooling fix (CRT-7M2D): the `/prawduct:pr` cumulative-Critic gate now judges its review record by **commit-coverage** rather than timestamp recency — it passes when the recorded review covers HEAD (or only docs changed since), and fails when real code changed since the review. This closes a correctness hole (a stale record could pass) and removes a workflow snag where every small post-review fix forced a full ~4-10 min review re-run. No change to how product builds are governed. Internal — most plugin users won't notice beyond smoother PRs.

## v2.0.8
Onboarding gets its own command. Setting Prawduct up in a repo is now **`/prawduct:onboard`** (new or existing repo — same command), instead of the mis-named `/prawduct:doctor`, which connoted health-check, not setup. `/prawduct:doctor` keeps its real job: health-check, repair, enable-gate, verify, and audit-learnings on an already-onboarded repo. The README quick start is trimmed to two steps — install the plugin once at the user level, then onboard any repo. No behavioral change to governance; existing repos are unaffected.

## v2.0.7
Sharper product-management methodology — and the first release in a while that consuming repos will *feel* in how the agent works, not just internals. Two additions reach every governed session through the digest. (1) **Proportional requirements rigor:** before building, the agent calibrates how hard to pin down requirements — and whether to research rather than rely on intrinsic knowledge — by *stakes × knowledge-confidence × volatility* (fast-moving or post-training-cutoff facts get verified, not recalled), and records answers it inferred rather than confirmed as vetoable `[ASSUMPTION: …]` instead of guessing silently. (2) An explicit **agent stance** (`/prawduct:methodology stance`): verify don't guess, stress-test before agreeing, offer the simpler alternative, frame decisions with concrete tradeoffs + a recommendation, plain language, research fast-moving designs, verify your own work before "done," scope discipline, and label confidence. Full model in `methodology/discovery.md` "Calibrate Rigor" and `methodology/agent-stance.md`. Plugin-governed repos pick this up automatically on next session.

## v2.0.6
Internal release/build-tooling fixes (REL-4T8N + three adjacent items). `regen-views` now regenerates **every** release-pending build plan in one pass — it enumerates each change-log `scope=` and resolves it to its plan file via frontmatter, so a batched multi-scope release no longer needs the `active_build_plan` pointer aimed at each plan in turn (it also no longer hard-fails when no single plan resolves). The derived `release-notes.md` renders each distinct scope of a batched release as its own sub-section instead of mis-aggregating them under one. `verify-chunk-refs` stops false-positiving on `` `path::symbol` `` references (it checks the path only). The `/prawduct:pr` merge flow now keeps the build plan when a feature→`develop` merge lands ahead of a batched `develop→main` release (deleting it only when the merge *is* the release). And the structural test suite ignores leftover `.claude/worktrees/` workflow checkouts. Plugin-governed repos: no behavioral change.

## v2.0.5
Internal quality + governance hardening, batched from four development scopes (roi-batch, roi-batch-2, evidence-deferral, cleanup-batch). Most visible to plugin users: a new `prawduct-hook test-evidence record` command that runs the suite and writes the `.test-evidence.json` the freshness gate reads (closing a reader-without-a-writer gap); the Stop gate now treats in-flight background work as "wait, don't waive" so it never silently skips the Critic; and the Critic flags substring assertions on "no behavior change" refactors. The rest is silent-degradation guards (regen-views exit codes, advisory-corruption surfacing), parser/gate hardening, behavior-preserving refactors, and added test coverage. Plugin-governed repos: no behavioral change beyond the new gate guidance.

## v2.0.4
New `prawduct:allow <scope>/<rule-id> -- reason` intentional-waiver pragma — one durable, language-agnostic way to mark a reviewed, intentional violation of a named principle (generalizing `prawduct:ok-broad-except`, which still works); `project/*`-scoped waivers stay opaque to the framework so plugin updates never break them. Also closes a governance-gate hole (the trivial/doc-only file-set bound now protects `skills/`, not the removed `agents/`) and clears 2.0 doc/coherence staleness. Plugin-governed repos: no behavioral change.

## v2.0.3
The v1 file-sync engine is fully retired. Governance now ships entirely from the plugin — no frozen sibling service, no committed framework templates, no sync machinery. Plugin-governed repos are unaffected (the engine they don't use is gone); any remaining v1 file-sync repo migrates onto the plugin with `/prawduct:migrate`.

## v2.0.2
Advisory probes run again in the plugin runtime. The `legacy-backlog-format` nudge (and every other post-sync advisory) was silently dead in v2 plugin repos — probe evaluation had been coupled to the removed file-sync `sync` step — so session-start never surfaced the prompt to run `/prawduct:backlog migrate`. The plugin SessionStart now evaluates the probe roster directly (local, fail-soft). Also: the file-sync→plugin **migration guide** now leads with the two-step action and the real install commands instead of burying them under background.

## v2.0.1
Default to **no commit/PR attribution trailers** (`Co-Authored-By`, `Signed-off-by`, "Generated with …"). Opt in per repo via `project-preferences.md` (`Commit attribution: none → co-authored`). The default is carried by the always-injected session digest, so it reaches every governed repo — including migrated ones whose only governance surface is the thin anchor.

## v2.0.0
Plugin distribution: Prawduct ships as a Claude Code plugin instead of files synced into each repo. Consuming repos commit **zero** framework files and get always-latest governance via marketplace auto-update — no stash/pop/merge papercuts. Mutable state stays in each repo's `.prawduct/`. Existing v1 file-sync repos keep working and migrate when ready (`/prawduct:migrate`).
