## Motivation

User reported (2026-05-23) that hallucinote agents were getting stuck in stop-hook loops during `.amxd` authoring. Pathology:

1. Chunk 1 typed `chunk` (default); active phase was human-only Max-for-Live patch authoring (a designer-handoff)
2. CRITIC REVIEW gate fires every session end: build plan active + code changes since session start + no fresh Critic findings
3. Agent has no path to satisfy gate — Critic legitimately can't review (no GO/NO-GO yet, partial code only)
4. Agent doesn't know `.gates-waived` exists — it's documented in `build-governance.md` but never named in the blocker text itself
5. Each turn: hook blocks → agent edits/retries → hook blocks again → tokens burn

The escape hatch exists. It's the discoverability that fails. The CRITIC REVIEW and REFLECTION blocker messages tell the agent what's blocked and how to satisfy the gate the *normal* way (run /critic, write a reflection) but never name the override for cases where the normal path is genuinely unavailable. Filed in backlog as a major bug.

**Companion structural fix** (loop-detection counter that escalates after N re-fires) is deferred to a follow-up. Discoverability fix is the high-ROI piece — once the agent reads "you can declare a waiver if this gate can't be satisfied this session," the loop ends. Counter is defense in depth for agents that still ignore the escape hatch.
