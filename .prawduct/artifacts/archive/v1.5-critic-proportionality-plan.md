## Motivation

User feedback (2026-05-21): Prawduct is being perceived as too onerous. Concrete symptoms:

1. Users issue prompts like *"do the build plan but defer Critic and PR reviewers until the very end"* — deferring governance because per-chunk Critic cost compounds.
2. Critic now has three modes (`chunk`, `final`, `cumulative`) and often complains it was invoked in the wrong mode. The mode-selection burden is on the caller; mistakes cost a re-run.
3. After a Critic round flags 1-2 BLOCKING findings and the builder fixes them, the re-review pays full review latency (~8 min cumulative) to confirm a one- or two-line resolution.

Three coupled fixes:

- **A. Mode inference** — `/critic` with no argument infers mode from git state + build-plan position. Output reports the chosen mode and rationale. Explicit `$ARGUMENTS` still overrides. Eliminates "wrong mode" complaints by removing the caller's choice.
- **B. Trivial-code fast-path** — new chunk `Type: trivial` for bounded mechanical changes (small LOC, no test deletion, no agent-instruction edits). Critic runs Goals 1-3 only; PR cumulative gate skips when the whole PR is trivial. The escape hatch PR #41 explicitly flagged as "open."
- **C. `verify-resolutions` delta mode** — backlog item filed 2026-05-20. Loads `.prawduct/.critic-findings.json`, narrows the review surface to files touched by prior BLOCKING/WARNING findings (plus new files since last review's commit). Reduces follow-up-fix re-review from ~8 min to ~1-2 min.

These compose: A's inference picks `verify-resolutions` automatically when the only delta since the last review is a fix to prior findings. B is independent. The "Three modes" become four (chunk, final, cumulative, verify-resolutions), but inference hides that complexity from the caller.

**Why now, not in v1.4**: v1.4 shipped the structural prerequisites — the `Type:` axis (F6), the cumulative gate (F2), the doc-only PR fast-path. v1.5 builds the proportionality layer on top.

**Backlog items resolved by this plan**:
- "Critic `verify-resolutions` / delta mode for follow-up fixes" (2026-05-20) — Chunks 01+02.
- "Small-bugfix proportionality (no code-change escape hatch from review gates)" (PR #41 out-of-scope) — Chunks 04+05.

## Requirements Confidence

**Level:** Medium

**Why:** Three coupled subsystems with clear shapes but two open decisions: (a) the `trivial` machine-enforced file-set rules need light tuning against historical chunks (LOC-bound dropped per user direction 2026-05-21 — trivial is a semantic judgment, not a size metric); (b) the naming of the new Type (`trivial` vs alternatives like `mechanical`, `bounded-code`) is a bikeshed that should be locked before Chunk 04 ships to avoid late renames. Inference logic (Chunk 03) is the highest-uncertainty piece — the rule set is sketched but real signal weights emerge from running it.

**Open assumptions / unknowns:**
1. Trivial-eligibility *file-set* rules — proposed bound is `no edits under agents/ | methodology/ | templates/`, `no CLAUDE.md edit`, `no test file deletions`, `no new files`. No LOC bound. The semantic claim is captured in a required `**Trivial because:**` rationale field in the chunk; Critic Goal 3 reads it and flags rationale-vs-diff mismatch.
2. Type name — `trivial` is the working name. Lock before Chunk 04 implementation lands.
3. Mode-inference precedence rules — when multiple signals conflict (e.g., session diff spans multiple commits AND last review's findings are unresolved), which wins? Sketched as `verify-resolutions > cumulative > final > chunk`; validate against ≥3 historical scenarios during Chunk 03.
4. Backward compat for product repos that explicitly invoke `/critic chunk` or `/critic final`: confirmed safe — explicit args bypass inference. Document loudly.

**What would raise confidence:** A 30-min spike against the last 10 prawduct chunks checking each one's diff against the proposed file-set rules + drafting what each one's `**Trivial because:**` rationale would look like would validate both the file-set rules and the rationale shape. Defer to Chunk 04's pre-impl design step.

### Chunk 03: `/critic` no-arg mode inference

- **Description:** Collapse the three-then-four-mode caller burden by making `/critic` with no `$ARGUMENTS` infer mode from git state + build-plan position. Explicit args still override (backward compat preserved — confirmed safe for product repos that always pass `chunk`/`final`/`cumulative`). Inference rules, in precedence order (highest wins):
  1. **`verify-resolutions`** when `.critic-findings.json` exists with BLOCKING/WARNING findings, `commit_reviewed` is set, current chunk's diff is a subset of that scope, and ≥1 finding-referenced file has been modified since.
  2. **`cumulative`** when the branch is ahead of base by ≥2 commits AND no cumulative-mode record exists for the current HEAD (the `/pr create` precondition path).
  3. **`final`** when the build plan's last unchecked chunk is currently in-progress (Status shows `[x]` for N-1 chunks + the current uncommitted one), or when no build plan exists and the session diff is medium+ size.
  4. **`chunk`** otherwise — mid-build-plan with prior chunks committed.
  Output (both stdout and findings JSON) names the chosen mode AND the rule that fired (`mode_chosen_by: "rule-1 verify-resolutions ..."` or `"explicit-args"` when overridden).
- **Type:** code
- **Depends on:** Chunks 01, 02 (verify-resolutions must exist to be inferable; `commit_reviewed` is the anchor).

### Chunk 04: `Type: trivial` chunk type + `**Trivial because:**` rationale + file-set enforcement

- **Description:** Add `trivial` to the allowed chunk Type values (currently `code | doc-only | cleanup | designer-handoff | cumulative-final`). Two enforcement layers:

  1. **Machine-enforced file-set bounds** (hard, structural): chunk diff has no edits under `agents/`, `methodology/`, or `templates/`; no edits to `CLAUDE.md`; no test file deletions; no new files. These are the catastrophic-blast-radius classes regardless of size — size is not a useful proxy for risk here.
  2. **Machine-enforced presence of rationale**: when `Type: trivial`, the chunk MUST include a non-empty `**Trivial because:**` field. Stop-hook parses for it; empty or absent → BLOCKING.

  **Size is not bounded.** Trivial is a semantic judgment, not a LOC metric — an 80-LOC project-wide rename can be trivial; a 5-line state-machine change cannot. The semantic claim lives in the `**Trivial because:**` rationale; Critic Goal 3 validates rationale-vs-diff fit in Chunk 05.

  **Critical fail-closed behavior** (per the Escape Hatches learning): a chunk declared `Type: trivial` that violates the file-set bounds OR lacks rationale is treated as `code` AND the stop-hook emits a BLOCKING note naming the specific violation. Over-declaring `trivial` is unsafe; the file-set check + required rationale are the structural enforcement.

  **Pre-impl design step** (runs before code in this chunk): audit the last 10 prawduct chunks against the proposed file-set rules; for each one that would be eligible, draft what its `**Trivial because:**` rationale would look like. This validates both the file-set rules and the rationale shape. Record the audit + locked rules in this chunk's commit message.

### Chunk 05: Critic protocol for `Type: trivial` (Goals 1-3 + rationale-vs-diff check) + `/pr` trivial fast-path

- **Description:** Wire `Type: trivial` into the Critic per-Type protocol matrix and add a PR-boundary trivial fast-path mirroring the doc-only fast-path.

  **Critic protocol for `Type: trivial`:** Goals 1 (Broken), 2 (Missing), 3 (Unintended), single-pass, scope = session diff. Goal 3 receives a new sub-check — **Rationale-vs-diff fit**: read the chunk's `**Trivial because:**` rationale (from Chunk 04's parser) and compare against the actual diff. If the rationale claims one kind of change but the diff contains another (e.g., "rename" but diff adds new function definitions; "type annotations" but diff modifies control flow; "add logging" but diff changes return values), emit **BLOCKING** for scope expansion. Low-information rationales (single word, generic phrases like "small change", "easy fix") get **WARNING** — the Critic can't validate fit when the claim is empty. This is the judgment backstop the file-set check can't provide.

  **PR fast-path:** every commit on `merge-base...HEAD` is fileset-eligible per Chunk 04's helper AND every chunk's rationale was Critic-passed in chunk-mode review. No aggregate size bound — same logic as per-chunk: size isn't the risk axis. When the fast-path fires, `/pr create` skips the cumulative-Critic gate and the PR reviewer agent (new subcommand: `check-pr-trivial`). Same fail-closed posture as doc-only: any error in evaluation falls through to full review.

## Risks

- **R1 — Inference picks the wrong mode and silently downgrades a review the user wanted heavy.** Mitigation: rationale is always reported (`mode_chosen_by`); explicit args bypass inference; fail-safe precedence (verify-resolutions only when scope clearly fits; cumulative > final > chunk in ambiguity). Track override frequency in the first weeks post-release — high override rate signals inference rules need tuning.
- **R2 — `Type: trivial` over-declaration bypasses meaningful review.** Three-layer mitigation: (a) file-set bounds enforced in stop-hook (Chunk 04) — catastrophic categories of change blocked structurally regardless of size; (b) required `**Trivial because:**` rationale enforced in stop-hook (Chunk 04) — empty/missing rationale produces BLOCKING; (c) Critic Goal 3 validates rationale-vs-diff fit (Chunk 05) — rationale claims "rename" but diff adds new function → BLOCKING; low-information rationale ("small change") → WARNING. Layers (a) and (b) are machine-enforced; layer (c) is judgment-enforced. Over-declaration is visible at every layer.
- **R2a — Low-quality rationales technically pass the presence check.** Mitigation: Critic Goal 3's rationale-vs-diff check emits WARNING for low-information rationales (single word, generic phrases). Methodology section ships with strong-vs-weak rationale examples to anchor expectations. If WARNING rate is high in early use, consider promoting to BLOCKING.
- **R3 — `verify-resolutions` scope misses an unrelated change smuggled in alongside a finding fix.** Mitigation: scope-widening demotion criterion (`len(new_files) > 2 * len(prior_finding_files) + 5`); stop-hook gate rejects verify-resolutions findings when the chunk diff is out-of-scope (Chunk 02).
- **R4 — Backward compat for product repos that explicitly invoke `/critic chunk`.** Confirmed safe: explicit `$ARGUMENTS` bypasses inference. No migration required. Document loudly in change-log so product owners don't worry.
- **R5 — SKILL.md token budget overrun.** Mitigation: Chunk 00 measures headroom; trim before adding (same as v1.4 Chunk 00 precedent).
