# v2.0.0 — Plugin Distribution: Build Plan

**Design:** `v2.0.0-plugin-distribution-design.md` (read first — this plan executes that design).
**Distribution change:** file-sync → Claude Code plugin. Major version (2.0.0).

## Requirements Confidence: **High**

- **Problem (one sentence):** framework files committed into consuming repos cause perpetual stash/pop/merge papercuts, stale/edited governance files, and no clean version signal.
- **Success (one sentence):** consuming repos commit zero framework files, get always-latest governance via a plugin, see their version + what changed at session start, and never fold framework drift into their own commits — while existing file-sync repos keep working until they explicitly migrate.
- **Out of scope:** changing the governance *content* (principles, methodology, Critic protocol stay as-is); rewriting product code in hallucinote or any consumer; removing backward-compat shims.

The three load-bearing unknowns are verified (plugin Stop hook blocks; `additionalContext` is supplemental; `autoUpdate` + semver gives always-latest-with-display). One real open item — **where the marketplace is hosted and who needs access** — is the explicit input for Chunk 2, not a blocker for Chunk 1.

## Governing invariant (do not violate)

Plugin ships **immutable read-only code only**; **all mutable state stays in each repo's `.prawduct/`**; **no mutable state shared between repos through the plugin** (design §2 — the v1 failure mode). Every chunk that touches the runtime must read/write only `${CLAUDE_PROJECT_DIR}/.prawduct/`.

## Verification strategy

Per chunk: acceptance criteria + `/critic`. Plus end-to-end exercise via `claude --plugin-dir <repo>` against this repo (and a throwaway test repo) — launch a session, observe the banner, run `/prawduct:*` skills, trigger the Stop-hook gate, confirm it blocks. Phase 4 adds parallel-worktree runs to prove self-containment. Headless checks use plain `claude -p` (not `--bare`).

## Phase 0 — Validate mechanics

### Chunk 1: Minimal installable plugin (thin vertical slice through the whole architecture)
- **Deliverable:** `.claude-plugin/plugin.json` (name `prawduct`, semver from `VERSION`); `hooks/hooks.json` with a SessionStart hook (bundled script via `${CLAUDE_PLUGIN_ROOT}`) that prints a version banner reading `plugin.json`; one trivial `/prawduct:ping` skill.
- **Acceptance:** `claude --plugin-dir . -p "/prawduct:ping"` against this repo loads the plugin, fires the hook (banner shows the semver), and `/prawduct:ping` resolves under the namespace. Proves load + hook + version-read + namespaced skill end-to-end.
- **Type:** code · **Done when:** acceptance met; `/critic`; committed; chunk marked `[x]`.

### Chunk 2: Marketplace + live install test (+ release-surface spike, design §5b)
- **Foreign API:** claude-code-plugins (marketplace/install surface) — **verify-api** by installing into a real throwaway repo, not from docs alone.
- **Deliverable:** `.claude-plugin/marketplace.json` with the plugin `source: { source: github, repo: brookstalley/prawduct, ref: "main" }` (public; same repo as the plugin; **pinned to `main`** per §5b); a throwaway test repo committing `extraKnownMarketplaces` (with `source.ref: "main"` + `autoUpdate: true`) + `enabledPlugins`.
- **Acceptance:** opening the test repo prompts install; plugin loads from the public marketplace; bumping `plugin.json` `version` and reopening auto-updates (banner shows new version). Closes Open Risk #3.
- **Release-surface spike (§5b — resolves the Open-Risk-2 sub-item):** empirically confirm the release trigger before Phase 2 builds the banner on it —
  1. a **version-bumped** commit on the test `main` ships to an `autoUpdate: true` consumer;
  2. a **non-version-bumped** commit on `main` does **not** ship (proves `version` is the cache-key gate);
  3. a commit on a `develop`-equivalent branch is **never** consumed (proves `ref: "main"` isolates the release surface);
  4. record whether `autoUpdate` tracks main's HEAD or the latest tag. If (2) fails (HEAD ships regardless of version), fall back to `ref: "vX.Y.Z"` tag-pinning (§5b fallback) and note it.
- **Type:** code · **Done when:** verify-api (live install) + release-surface spike done; acceptance; `/critic`; committed.

## Phase 1 — Port the framework into the plugin (built alongside file-sync; non-breaking)

### Chunk 3: Skills → `/prawduct:*`
- **Deliverable:** move `critic, pr, janitor, learnings, backlog, prawduct-advisory, prawduct-doctor` into plugin `skills/`; they read `${CLAUDE_PROJECT_DIR}/.prawduct/`. Sweep skill-to-skill cross-references to `/prawduct:*`.
- **Acceptance:** each skill runs under `--plugin-dir` against this repo with identical behavior to its current `.claude/skills/` copy; no internal reference still says bare `/critic` etc.
- **Type:** code · **Done when:** acceptance; `/critic`; committed.

### Chunk 4: Agents → plugin
- **Deliverable:** move `critic` and `pr-reviewer` agents into plugin `agents/`; wire skill→agent references.
- **Acceptance:** `/prawduct:critic` and `/prawduct:pr` invoke the plugin-bundled agents with restricted tools intact.
- **Type:** code · **Done when:** acceptance; `/critic`; committed.

### Chunk 5: Runtime python + hooks (architectural keystone)
- **Deliverable:** port `tools/product-hook` + governance bits of `tools/lib` into plugin `bin/` + `lib/`, reading/writing **only** `${CLAUDE_PROJECT_DIR}/.prawduct/`; wire `hooks/hooks.json` SessionStart (briefing) + **Stop (Critic gate + reflection)**. Exclude sync-only machinery from the plugin runtime (sync stays in the legacy shim path only).
- **Acceptance:** session-start briefing renders from the plugin; the Stop-hook Critic gate **blocks** session end when code changed against an active build plan with no findings (verified by deliberately triggering it); no path writes outside `.prawduct/`.
- **Type:** code · **Critic mode:** final (override — keystone whose coherence later chunks build on) · **Done when:** acceptance; `/critic` (final); committed.
- **★ Governance checkpoint:** review the whole runtime/hook surface and the invariant (§2) before widening.

### Chunk 6: Methodology, templates, guidance digest
- **Deliverable:** bundle `methodology/`, `templates/`, governance text into the plugin; SessionStart `additionalContext` digest; on-demand readers (`/prawduct:methodology`, `/prawduct:building`, …).
- **Acceptance:** methodology is readable via plugin skills with no repo copy; digest appears at session start.
- **Type:** code · **Done when:** acceptance; `/critic`; committed.

## Phase 3 — Coexistence + migration tooling

### Chunk 8: Mutual stand-down detection
- **Deliverable:** plugin hook detects legacy file-sync mode (committed `product-hook` wired in settings.json / sync-manifest with managed files) and stands down with a "run `/prawduct:migrate`" notice; legacy committed `product-hook` symmetrically detects the plugin and stands down.
- **Acceptance:** a repo with both installed fires exactly one governance path (no double banner, no double `/critic`); a pure-legacy repo is unaffected.
- **Type:** code · **Done when:** acceptance; `/critic`; committed.

### Chunk 9: `/prawduct:migrate` cutover (graceful; preserves all product state)
- **Deliverable:** migrate command (via prawduct-doctor) performing the cutover as one reviewable, reversible commit.
- **REMOVE (framework mess committed by file-sync):** framework skills under `.claude/skills/` (critic, pr, janitor, learnings, backlog, prawduct-advisory, prawduct-doctor), `tools/product-hook`, framework `tools/lib/*`, the `<!-- PRAWDUCT:BEGIN/END -->` block in CLAUDE.md, the committed hook wiring in `.claude/settings.json`, and the now-inert `.prawduct/sync-manifest.json`.
- **NEVER TOUCH (product-owned, mutable — the place-once contract):** everything else under `.prawduct/` — `project-state.yaml`, `learnings.md`, `learnings-detail.md`, `backlog.md`, `change-log.md`, `artifacts/`, `.critic-findings.json`, reflections — and **all** non-framework project files (the product's own skills, `src/`, `tests/`, MCP server, configs). Derive the REMOVE set from the framework registry (write-strategy ≠ place-once), never from "any path prawduct ever placed."
- **Then:** commit the install reference; record `distribution: plugin` in `project-state.yaml`; leave shims in place.
- **Acceptance:** on a copy of a real file-sync repo (hallucinote), migrate produces one reviewable commit; a diff confirms **zero** changes to the NEVER-TOUCH set; the repo runs fully on the plugin afterward; re-running migrate is a no-op.
- **Type:** code · **Critic mode:** final (override — destructive cleanup; safety + coherence matter) · **Done when:** acceptance; `/critic` (final); committed.
- **★ Governance checkpoint:** migration correctness, the preservation contract, and backward-compat (un-migrated repos still work).

### Chunk 10: Thin static CLAUDE.md anchor
- **Deliverable:** the small static governance anchor template (§4); product-CLAUDE.md reduction (remove big block, keep product-specific + anchor); migrate applies it.
- **Acceptance:** migrated repo's CLAUDE.md has only product content + the version-free static anchor; re-running migrate is idempotent (no drift).
- **Type:** code · **Done when:** acceptance; `/critic`; committed.

## Phase 5 — Deprecate file-sync + docs sweep

### Chunk 13: Remove the mechanism *and its name*
- **Deliverable:** remove file-sync engine from the active path; grep-sweep the **name** across `tools/ templates/ methodology/ agents/` (learning: removing a mechanism requires removing its name). **Keep shims** for un-migrated external repos.
- **Acceptance:** no dangling references to the removed sync path; shims still resolve for legacy repos.
- **Type:** cleanup · **Done when:** acceptance; `/critic`; committed.

### Chunk 14: Docs/README sweep + learnings (cumulative-final)
- **Deliverable:** update README, CLAUDE.md, layout diagrams, briefing docs to plugin reality; **document the gitflow release model (§5b) where contributors will find it** — a `docs/` "Release process" section: develop=integration / main=release, the consumer pins `ref: "main"`, and the release checklist (merge `develop`→`main` · bump `plugin.json` `version`/`VERSION` · flip changelog `status=merged`→`shipped` + add `release=`/`scope=` tags · `regen-views` · tag `vX.Y.Z` · banner bump). Capture the §5a learning nuance (governance-as-CI overrides "auto-enable belongs with visibility" when the owner models it that way) in `learnings.md`.
- **Acceptance:** no doc still describes file-sync as the primary path; the release process is documented; learnings updated.
- **Type:** cumulative-final · **Done when:** acceptance; `/critic cumulative` against merge-base; `/pr`.
