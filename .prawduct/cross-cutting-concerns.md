# Cross-Cutting Concerns Registry

Maps concerns to pipeline coverage. Use this as a starting point for completeness checks — but think about what's missing, not just what's listed.

**Pipeline dimensions:**
- **Discovery** — Is this concern surfaced during discovery?
- **Artifact** — Does at least one artifact template specify it?
- **Builder** — Does the build methodology guide implementation?
- **Critic** — Does the Critic have a check that validates it?

## Known Gaps

- **Cost awareness** lacks builder guidance and Critic enforcement. Currently proportionate — most products don't need cost gates during build. Revisit if cost overruns become a pattern.
- **Error handling** — resolved, with one leg being replaced. Pipeline coverage: discovery surfaces approach, builder has the Exception Handling section using the general intentional-waiver pragma `prawduct:allow prawduct/broad-except -- reason` (spec `docs/waivers.md`; legacy `prawduct:ok-broad-except` still honored), the Critic verifies each waiver is legitimate (reason present, genuine boundary), and the compliance canary flags reason-less waivers. **The canary's unwaived-broad-catch detection is being retired** (LNG-5W8R): per the 2026-07-29 norm, prawduct does not re-implement a rule an ecosystem's tooling owns, and that check is a Python/JS/Go-only regex duplicating ruff `E722`/`BLE001` while silently no-opping on Swift, Rust, C# and C. Coverage does not drop — the judgment leg is already the Critic's, and ruff lands before the check is removed. The reason-less-waiver check stays: it is language-agnostic and models nothing a linter owns.
- **Dependency management** has no discovery trigger. Dependencies are a planning concern. This is by design.
- **Learnings relevance filtering**: Session briefing now shows a topic index of section headers instead of the last 3 rules. Learnings are consumed at Critic review, PR review, planning, and building. Future work: a `/learnings [topic]` skill for targeted lookup without loading the full file. Tracked as a potential enhancement, not blocking.
- **Strategy-class artifact coverage** — covered end-to-end (discovery records characteristics → coverage chain layers 0-1-2 → doctor coverage check + scaffold → Critic owns stub decision-quality). The last gap closed 2026-07-17: `templates/architecture.md` now exists (GOV-2T6K), so every strategy-class artifact hands its author a scaffold.
- **API design (produced)** — covered (discovery → `api-contract.md` artifact + decision blocks → planning/building → Critic Goal 2 WARNING), with retroactive detection via the `api-versioning` advisory probe + doctor #9 + janitor theme. Two deliberate follow-ups deferred (filed to backlog): a *coded auto-detect* variant of the `**Exposed API:**` Critic trigger (vs. today's author-declared field, which mirrors Foreign API's opt-in model), and a *standalone error-model* artifact/template (today the error-model decision lives in the api-contract template + the `api_error_model_approach` block). Both are stronger-guarantee enhancements, not gaps in the shipped coverage.
